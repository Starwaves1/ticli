# Cached metadata never expires; it is held to its own 100 MB cap

To be a real offline player, everything the user has opened (library, album track lists, artist pages, recent searches) stays on disk and paints first, with its age shown, until a live fetch replaces it. The 30-day expiry goes: stale-but-labelled beats nothing when offline. Size is bounded instead by a 100 MB metadata cap, separate from the audio budget, evicting least-recently-opened lists first and the user's own library (`playlists`, its playlists' tracks, `favorites:*`, `mixes`) last.

As built: the player keeps a connectivity state (online / offline / signed_out) and pushes it to every client. With stored tokens and no network it starts offline, the tokens adopted onto the session without the `GET /sessions` tidalapi could not complete. Only an action that needs TIDAL leaves offline, by re-running `load_oauth_session` once (single-flight; never a timer or probe, ADR-0003). TIDAL refusing the tokens there (the token endpoint's 400/401, or a 401 with no refresh tried) is signed_out; a 5xx or transport failure stays offline. A 401 on an ordinary request while online runs the same single-flight load. Signed out, the tokens stay, the player keeps playing, and a human signs in again with [o]; nothing automatic goes through logout. Offline, reads answer from this cache with their age, search and resolve answer from the user's own playlists, favourites and downloads, writes are refused rather than queued, and next and auto-advance skip entries with no local copy.

The index is one file per list (`lists/`, named by a hash of the key) plus a small manifest of each list's fetch time, last open, size and library flag. A read opens only its own list's file; a write replaces that file and then the manifest, both atomically, so a crash leaves at worst an orphan, never a torn manifest. Opens update `used` in memory and reach the manifest with the next write. Eviction unlinks files and goes down to 90% of the cap so it is not paid on every write. The single `metadata.json` of earlier versions is split into list files on first load, then removed. Measured: the one-file index cost 838 ms per write at the cap; per-list files cost 1 to 19 ms.
