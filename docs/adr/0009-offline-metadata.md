# Cached metadata never expires; it is held to its own 100 MB cap

To be a real offline player, everything the user has opened (library, album track lists, artist pages, recent searches) stays on disk and paints first, with its age shown, until a live fetch replaces it. The 30-day expiry goes: stale-but-labelled beats nothing when offline. Size is bounded instead by a 100 MB metadata cap, separate from the audio budget, evicting least-recently-opened lists first and the user's own library (`playlists`, its playlists' tracks, `favorites:*`, `mixes`) last.

As built: the player keeps a connectivity state (online / offline / signed_out) and pushes it to every client. With stored tokens and no network it starts offline, the tokens adopted onto the session without the `GET /sessions` tidalapi could not complete. Only an action that needs TIDAL leaves offline, by re-running `load_oauth_session` once (single-flight; never a timer or probe, ADR-0003). A 401 there is signed_out: the tokens stay, the player keeps playing, and a human signs in again with [o]; nothing automatic goes through logout. Offline, reads answer from this cache with their age, search and resolve answer from the user's own playlists, favourites and downloads, writes are refused rather than queued, and next and auto-advance skip entries with no local copy.

The index is one file, rewritten whole on each write; at the cap that is 100 MB per write. Per-list files would be the next step if that shows.
